# Front async / SSE node enrichment

System: `front`. Feature: `async-sse`.
OpenSpec change: `front-async-sse` → `specs/front/async-sse/spec.md`.

Source: `L2/02.EPIC-ANGULAR-CODIFICATION.async-sse.md`, `L2/02.EPIC-ANGULAR-CODIFICATION.async-infra.md` (EPIC-002). Companion: `back-async-sse`, `infra-async-persistence`.

| ID | Status | Requirement |
| --- | --- | --- |
| FASSE-001 | registered | Synchronous path (when generation is fast): user opens the page or refreshes the panel; one request (or a short chain) returns the full set of nodes; `completeDowload` runs only when the list is ready; one `notifyDataChanged` then the viewer paints the full flat list. The user sees a download state until the list is complete, then the whole viewer content appears. |
| FASSE-002 | registered | When building or enriching nodes takes too long to block the page, the UI MUST NOT wait for complete synchronous generation. Return a simplified list as soon as possible, enrich in the background, and push updates to the open page without reload or navigation. Push transport is SSE: Nest exposes an SSE stream; the front adapter opens that channel and applies each event to the cache and the panel's node list. Requests that start work stay on normal HTTP. |
| FASSE-003 | registered | Front adapter cache (browser / front service) is one store of truth for heavy pages: fast return on leave/return; holds the latest list including SSE enrichments; not durable across devices. |
| FASSE-004 | registered | Request path on the front: page asks the front adapter for the node list; adapter looks in the front cache — on hit, return cached list immediately and still open (or keep) the SSE channel; on miss, HTTP GET Nest for that list; frontend feeds the panel (`completeDowload` / merge into `dataModelRoot`) and paints through the normal viewer path; not-fully-ready nodes use `NeoComDelayed` / `isReady()`; in parallel the adapter opens an SSE channel scoped to that list. First paint does not wait for enrichment to finish. |
| FASSE-005 | registered | Enrichment path on the front while the page stays open: on each SSE event the adapter merges into the adapter cache and notifies the panel so `dataModelRoot` / node fields update and `notifyDataChanged` re-runs; the viewer refreshes that row in place. On leave/return, the adapter serves the cache (including earlier SSE enrichments) for instant paint while unfinished or stale items may still refresh over SSE. |
| FASSE-006 | registered | Blueprint list with manufacture index (front): page/panel asks the adapter for the pilot's blueprint list; cache hit returns cached blueprints and opens SSE; otherwise HTTP then first paint with delayed/partial rows; on SSE merge the panel updates that row with no reload; return visit paints last known indexes from cache then continues SSE. |
| FASSE-007 | registered | Opening a heavy page MUST NOT block until every node is fully computed — partial presentation is required. The front adapter is the single entry for list fetch: cache first, then Nest HTTP, then merge SSE into cache and UI. Updates after first paint change the existing UI in place. The same node → collaboration → viewer → registry → render pipeline is reused. A delayed / not-ready node MUST be renderable in a safe partial state; when it becomes ready via SSE, the same row updates. Front consumes Nest `@Sse()` via `EventSource` or equivalent authenticated stream consumer. |
| FASSE-008 | registered | Frontend adapter: single entry for list fetch — cache first, then HTTP, then SSE merge. First-party Angular services under the front app (industry/manufacture adapters). HTTP via `@angular/common/http`. Viewer integration: SSE merges call the same `dataModelRoot` / `notifyDataChanged` path; existing panel/viewer stack; no new UI library. |
| FASSE-009 | registered | Frontend SSE client: open a scoped event stream; apply `node-updated` (and similar) events to cache and panel. Prefer a client that supports auth headers/cookies reliably. Native `EventSource` is enough only if cookie auth on the stream is acceptable; otherwise add a fetch-based SSE helper (for example `@microsoft/fetch-event-source` or an equivalent small wrapper). Bridge events into RxJS observables for the panel. |
| FASSE-010 | registered | Frontend cache: survive leave/return on the same browser without waiting for Nest. First-party cache service; memory for the session plus optional `localStorage` / IndexedDB for longer retention. No mandatory third-party cache library. |
