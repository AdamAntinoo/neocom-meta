Topic: client-side EVE Image Server URL contract for portraits, logos, and type icons (EPIC-006 Media section; same contract restated from EPIC-004).

## Media from the EVE Image Server

| ID | Status | Requirement |
| --- | --- | --- |
| UI-MED-001 | registered | Portraits, corporation/alliance logos, and type icons SHALL be loaded by the **client** directly from the [EVE Image Server](https://developers.eveonline.com/docs/services/image-server/) |
| UI-MED-002 | registered | The NeoCom **backend** SHALL NOT proxy, store, or return these image bytes |
| UI-MED-003 | registered | A render SHALL build the image URL from the id it already has — pattern `https://images.evetech.net/{category}/{id}/{variation}?size={size}` |
| UI-MED-004 | registered | URL categories / variations SHALL follow this table: pilot portrait → `characters` / `portrait`; corporation logo → `corporations` / `logo`; alliance logo → `alliances` / `logo`; item/module/resource icon → `types` / `icon`; hull or type render → `types` / `render`; blueprint original → `types` / `bp` |
| UI-MED-005 | registered | When `size` is supplied it SHALL be a power of two from **32** to **1024**; omit `size` only when the original size is acceptable |
| UI-MED-006 | registered | Image `tenant` defaults to **`tranquility`** |
| UI-MED-007 | registered | When a character, corporation, or alliance id is missing, the URL SHALL use id **`1`** (documented default portrait or logo) |
| UI-MED-008 | registered | Clients MAY request the URL as a CDN; they SHALL NOT cache the image bytes through the backend |
