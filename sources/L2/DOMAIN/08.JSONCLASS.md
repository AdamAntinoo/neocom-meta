System: `domain` (capabilities also `back/jsonclass`, `front/jsonclass`). Feature: `jsonclass`.
OpenSpec change: `domain-jsonclass` → `specs/domain/jsonclass/spec.md`, `specs/back/jsonclass/spec.md`, `specs/front/jsonclass/spec.md`.

Source: `L2/04.EPIC-MODELS.md` (Interchange: `jsonClass` on domain responses / L1 Section 22).

| ID | Status | Requirement |
| --- | --- | --- |
| DOM-JSONCLASS-001 | applying | When the back returns a published domain model (single object or list element), the payload SHALL include a field named **`jsonClass`** whose value is the programme domain type name for that instance |
| DOM-JSONCLASS-002 | applying | Front render selection for those payloads SHALL use `jsonClass` (same contract as NeoCom nodes / EPIC-002); consumers MUST NOT guess the type from URL alone when `jsonClass` is present |
| DOM-JSONCLASS-003 | applying | `jsonClass` values for published models SHALL align with `neocom-domain` exports and the EPIC-004 register (e.g. **PilotV2**, not an unversioned `Pilot`, when the programme type is PilotV2) |

The value of `jsonClass` SHALL match the type name published for that model in `neocom-domain`. The back SHALL NOT omit `jsonClass` for those payloads, invent a different discriminator name, or use an ESI-only type name when a programme domain type exists.
