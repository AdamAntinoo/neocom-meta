# Coverage measurement and SonarCloud quality gates

System: `cicd`. Feature: `coverage-sonar`.
OpenSpec change: `cicd-coverage-sonar` → `specs/cicd/coverage-sonar/spec.md`.

Source: `L2/03.EPIC-TESTING.coverage-sonar.md` (EPIC-003).

| ID | Status | Requirement |
| --- | --- | --- |
| COV-001 | registered | The project SHALL provide a **tool to measure and control code testing coverage**. Coverage results SHALL be available to developers locally and in CI so gaps can be found before a feature is completed. |
| COV-002 | registered | The project SHALL define **quality-gate rules** that use coverage (and related test outcomes) to pass or fail a change. A feature SHALL NOT be considered complete when required gates fail. |
| COV-003 | registered | Gate thresholds and which suites they apply to (unit, acceptance/Cypress, and any later layers) SHALL be recorded so agents and CI enforce the same rules. |
| COV-004 | registered | NEOCOM projects SHALL **report to SonarCloud** so coverage, quality gates, and other quality findings are checked in one place. |
| COV-005 | registered | CI SHALL upload analysis (and coverage where applicable) to SonarCloud; a change that fails the configured SonarCloud quality gate SHALL NOT be considered complete. |
