Topic: versioned panels (`vn-`), `app-page-header` controller, `v1-application-info-render` and `v1-server-status-render` Appearance.

## Versioned panels (`vn-`)

| ID | Status | Requirement |
| --- | --- | --- |
| UI-VER-001 | registered | Panels/renders bound to domain models use **`vn-`** in their public selector and path names |
| UI-VER-002 | registered | The `vn` tracks the domain type version (`ApplicationInfoV1` → `v1-application-info-render`; `ServerStatusV1` → `v1-server-status-render`; `PilotV2` → `v2-pilot` / versioned pilot panel as specified) |
| UI-VER-003 | registered | Unversioned legacy panels (`app-info-panel`, `server-info-panel`) are not used for new work |

## Common header (`app-page-header`)

| ID | Status | Requirement |
| --- | --- | --- |
| UI-HDR-001 | registered | Selector **`app-page-header`**. Pages that need a header put `<app-page-header …>` as the first element in the page HTML |
| UI-HDR-002 | registered | Page templates SHALL NOT compose header renders or legacy `app-info-panel` / `server-info-panel` directly; those live inside `app-page-header` |
| UI-HDR-003 | registered | Variant **`-APP-`** (default, secured pages): provide **ApplicationInfoV1** + **ServerStatusV1** (+ application menu when specified) to their `v1` renders |
| UI-HDR-004 | registered | Variant **`-AUTH-`** (login, login-callback, similar): provide **ApplicationInfoV1** only — no ServerStatusV1, no application menu |
| UI-HDR-005 | registered | `app-page-header` owns `cy-section-name="header"` and hosts the render slots (layout / colour of each render) |
| UI-HDR-006 | registered | Exception region stays **under** the header, owned by the page (or a later shared exception slot), not inside `app-page-header` |
| UI-HDR-007 | registered | Header controller locates **ApplicationInfoV1** and **ServerStatusV1** via **data providers** (same pattern as other feature data providers) |
| UI-HDR-008 | registered | Header controller injects each obtained domain node into the render resolved by `jsonClass` (render registry / standalone-node path from EPIC-002). Renders call node accessors only |
| UI-HDR-009 | registered | Domain models: **ApplicationInfoV1** / **ServerStatusV1** (EPIC-004). Renders: **`v1-application-info-render`**, **`v1-server-status-render`**. Legacy unversioned panels are transitional |

## Application info Appearance (`v1-application-info-render`)

| ID | Status | Requirement |
| --- | --- | --- |
| UI-AIP-001 | registered | Application info in the header SHALL be painted by **`v1-application-info-render`** (model-strip name / selector), not by composing legacy `app-info-panel` from pages |
| UI-AIP-002 | registered | The render SHALL use **`neocom-panel panel-white`** chrome and `cy-section-name="app-info"` |
| UI-AIP-003 | registered | The panel contents SHALL show **name** (uppercase), **version**, and **copyright** from **ApplicationInfoV1** as on the model-strip Appearance |
| UI-AIP-004 | registered | Name uses **Elemental** (large, white); version uses **Elemental** (smaller, yellow); copyright uses **Open Sans** (small) |
| UI-AIP-005 | registered | On `-AUTH-`, `app-page-header` hosts this content panel only; on `-APP-`, it hosts this panel together with the server-status content panel |

## Server status Appearance (`v1-server-status-render`)

| ID | Status | Requirement |
| --- | --- | --- |
| UI-SSP-001 | registered | Server status in the header (`-APP-`) SHALL be painted by **`v1-server-status-render`**, not by composing legacy `server-info-panel` from pages |
| UI-SSP-002 | registered | The render SHALL use **`neocom-panel panel-blue`** chrome and `cy-section-name="server-info"` |
| UI-SSP-003 | registered | Line 1: server name **left** and status **right**, both **Elemental 14px** |
| UI-SSP-004 | registered | Metric lines SHALL use **Open Sans**, with labels left and **values right** |
| UI-SSP-005 | registered | Metric labels SHALL use colour **orange `#ffa500`** (programme field-label orange), not red / `panel-red` / `#ff3300` |
| UI-SSP-006 | registered | Panel height SHALL **match** the application-info panel; adjust line separation / padding (or reduce font size) to fit |
| UI-SSP-007 | registered | Line 2 (`CAPSULEERS`) SHALL show **SDE version** and **players count** on that same line; line 3 is **NEXT DT**; SHALL NOT show Backend or a separate SDE VERSION line |
