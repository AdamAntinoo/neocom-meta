Topic: Dashboard landing page layout, feature listing panel, parent/subfeature navigation, breadcrumb. Legacy DASH-001…009 remain imported comparison on L1; prefer these UI-DASH rows when they conflict. Registered into `FRONT/04.DASHBOARD.md` / `front-dashboard-shell` (including UI-DASH-015).

## Dashboard (landing page)

| ID | Status | Requirement |
| --- | --- | --- |
| UI-DASH-001 | registered | Dashboard is the application landing page after successful login and character selection |
| UI-DASH-002 | registered | Dashboard is secured; unauthenticated users or users without a selected character SHALL not see it as the post-login home |
| UI-DASH-003 | registered | Dashboard layout rows, in order: `app-page-header`; pilot & corporation; breadcrumb (from Dashboard); feature list listing panel |
| UI-DASH-004 | registered | The feature list row is a listing panel: **data provider** supplies feature domain data; each item is shown with a **feature render** like other renders |
| UI-DASH-005 | registered | Dashboard starts with **`<app-page-header />`** (`-APP-` variant); header controller provides **ApplicationInfoV1** and **ServerStatusV1** to their `v1` renders |
| UI-DASH-007 | registered | Second row includes the **pilot information** panel and the **corporation information** panel |
| UI-DASH-008 | registered | Third row is the navigation **breadcrumb**, starting at the Dashboard; each crumb is a **link** to its page reference so the trail is usable for navigation |
| UI-DASH-009 | registered | Feature list does not permanently hard-code feature slots in the page template; it consumes the provider list through the standard listing + render path |
| UI-DASH-010 | registered | Breadcrumb trail on non-Dashboard secured pages reflects Dashboard → … and each step remains a navigable link to that page |
| UI-DASH-012 | registered | Selecting a parent feature (e.g. Industry) navigates to that feature’s dashboard/page; that page shows a **new** feature list for Industry subfeatures |
| UI-DASH-013 | registered | Feature dashboards reuse the secured page chrome pattern (header, breadcrumb reflecting Dashboard → parent → …, feature list row) as applicable |
| UI-DASH-014 | registered | Subfeature nesting follows the navigation structure; each level’s provider supplies only the features for the current parent context |
| UI-DASH-015 | registered | On the Dashboard (and secured pages that reuse the same chrome), separations between **header first line** and **pilot & corporation** row, between **pilot** and **corporation**, between **app-info** and **server-info**, and the **border inset** of those panels SHALL use **UI-GEO-001** (default panel gap) — no larger page-local padding/gap on the pilot row (defect DEF-IB-006) |
