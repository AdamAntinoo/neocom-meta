# Pilot panel

System: `front`. Feature: `pilot-panel`.
OpenSpec change: `front-pilot-panel` → `specs/front/pilot-panel/spec.md`.

The HTML fragments in the original note illustrate the variant marker and the field markup. They are not extra behavior.

| ID | Status | Requirement |
| --- | --- | --- |
| PANEL-001 | registered | The application defines a panel that renders the UI of the Pilot model |
| PANEL-002 | registered | The input to the panel is the unique identifier of an EVE character |
| PANEL-003 | registered | The panel renders the public and the private sides of the pilot data. If the credential is not available, the private data can be hidden |
| PANEL-004 | registered | The panel conforms to the neocom panel model |
| PANEL-005 | registered | The panel color is white with the standard background |
| PANEL-006 | registered | The render code for the public data is `-PILOT-PUBLIC-VARIANT-` |
| PANEL-007 | registered | The render for the private data complementing the public data is `-PILOT-VARIANT-` |
| PANEL-008 | registered | The render used on pilot listings is `-PILOT-LIST-VARIANT-`, and it renders only a partial of the data available |
| PANEL-009 | registered | On pilot listings the current active pilot is rendered with a greenish background |
| PANEL-010 | registered | The panel is a `div` with `cy-element-name=pilot` and `cy-element-type=panel` |
| PANEL-011 | registered | Rows are `div`s that add the pilot attribute fields and their contents |
| PANEL-012 | registered | Field tags are `cy-field-label` and `cy-field-value` |
