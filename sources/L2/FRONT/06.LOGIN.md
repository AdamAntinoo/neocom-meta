| ID | Status | Requirement |
| --- | --- | --- |
| LOGIN-001 | registered | A guarded page starts login when `neocom_access` is missing or its `Max-Age` has elapsed. The front filter writes the current URL into `neocom_return` and sends the browser to the login page. After login completes, the browser returns to that URL. `neocom_return` uses `Path=/` and `SameSite=Lax`, and it lasts until the callback redirects or 20 minutes |
| LOGIN-002 | registered | The development registration is named New Neocom Infinity. The callback is `http://localhost:6001/app/login-callback` because the front `base href` is `/app`. The client id is `4664722d6bd0415683a04519e738a5fc`. The client secret is not written in the epic. Locally the client id and the client secret are written in the front configuration file for that environment, in the clear. The first login requests every registered scope name, joined with a single space. There is no wildcard and the request does not send `esi-*`. The registered names are: `esi-location.read_ship_type.v1`, `esi-wallet.read_character_wallet.v1`, `esi-universe.read_structures.v1`, `esi-ui.write_waypoint.v1`, `esi-characters.read_fw_stats.v1`, `esi-characters.read_freelance_jobs.v1`, `esi-activities.read_character.v1`, `esi-access.read_lists.v1`, `esi.activity.char:read`, `esi.cosmetic.char:read`, `publicData`, `esi-location.read_location.v1`, `esi-wallet.read_corporation_wallet.v1`, `esi-search.search_structures.v1`, `esi-characters.read_contacts.v1`, `esi-assets.read_assets.v1`, `esi-planets.manage_planets.v1`, `esi-ui.open_window.v1`, `esi-characters.write_contacts.v1`, `esi-markets.structure_markets.v1`, `esi-characters.read_loyalty.v1`, `esi-characters.read_chat_channels.v1`, `esi-characters.read_medals.v1`, `esi-characters.read_standings.v1`, `esi-characters.read_agents_research.v1`, `esi-industry.read_character_jobs.v1`, `esi-markets.read_character_orders.v1`, `esi-characters.read_blueprints.v1`, `esi-characters.read_corporation_roles.v1`, `esi-location.read_online.v1`, `esi-characters.read_fatigue.v1`, `esi-wallet.read_corporation_wallets.v1`, `esi-characters.read_notifications.v1`, `esi-assets.read_corporation_assets.v1`, `esi-industry.read_corporation_jobs.v1`, `esi-markets.read_corporation_orders.v1`, `esi-industry.read_character_mining.v1`, `esi-industry.read_corporation_mining.v1`, `esi-planets.read_customs_offices.v1`, `esi-characters.read_titles.v1`, `esi-alliances.read_contacts.v1` |
| LOGIN-003 | registered | The login page reuses `OAuthEnabledComponent` from `neocom-infinity-frontend/src/app/pages/OauthEnabled.component.ts`, through `BackgroundOauthEnabledComponent`, the same subclass `v1-start-page` extends. `getLoginLink()` calls `composeLoginLink()`, which reads `environment.loginLinkData` and appends `response_type`, `client_id`, `state`, `redirect_uri`, and `scope`. The scope value is `environment.loginLinkData.scope`, the same `EVE_SSO_SCOPES` value. The page writes that same `state` into `neocom_sso_state` before the browser leaves for EVE. The back does not build the authorize URL |
| LOGIN-004 | registered | `neocom_sso_state` uses `Path=/` and `SameSite=Lax`. It holds the `state` from `getLoginLink()` and lasts until the callback accepts or rejects it, or 20 minutes. The callback rejects the request when the query `state` differs from this cookie and does not call `addCharacter`. On a match it clears `neocom_sso_state`. If the player cancels at EVE, the browser returns with no code, the login page is shown again, and `neocom_return` stays so a retry still knows the destination |
| LOGIN-005 | registered | `neocom_access` is readable by the front. It is not `HttpOnly`, so page scripts and a test can read it from `document.cookie`. The value is the access token, the character name, and the character id. It uses `Path=/`, `SameSite=Lax`, and `Max-Age=1200`. The front filter treats a missing cookie as token not present and an elapsed `Max-Age` as expired. The front does not refresh the token and does not run a timer. When the back answers `401`, the front deletes `neocom_access` and returns to the login page |
| LOGIN-006 | registered | The UI can change the active character without a new login. It writes another character name and character id into `neocom_access` when that character is already stored. That does not start a new SSO login |
| LOGIN-007 | registered | The login page follows `neocom-infinity-frontend` `v1-start-page`, with `app-info-panel` from `neocom-front` above that panel. `app-info-panel` (`src/app/panels/app-info-panel`) reads the front environment and shows the application name in uppercase, the version, and the copyright. The current development values are `neocom-front`, `0.0.0`, and `© 2019,2024 Dimensinfin Industries`. The title is `NeoCom / SSO EVE Online`. While the page is checking the session it shows `VALIDANDO AUTENTICACION DEL PILOTO...`. When there is no session it shows the EVE login button, `cy-name="EVE-login-button"`, using `assets/media/eve-sso-login-white-large.png`. The button href is `getLoginLink()`. A footer carries the copyright line. The validation message and the login button are alternatives |
| LOGIN-008 | registered | The callback page is required to finish login. It lives in `neocom-front/src/app/pages/login-callback-page` and is served at `/login-callback`. EVE returns the browser to `http://localhost:6001/app/login-callback?code=<authorization_code>&state=<state>`. The page follows `v1-login-validation-page`. It reads `code` and `state` and keeps `app-info-panel` at the top. The progress region shows `Waiting for code authentication...` and the authorization code, or `-AWAITING-CODE-` when `code` is absent. When `code` is missing or `state` does not match `neocom_sso_state`, the exception region shows `Exception: EXCEPTION` and the message, and the back does not call `addCharacter`. On a match the callback continues and the browser opens `neocom_return` |
