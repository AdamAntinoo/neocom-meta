| ID | Status | Requirement |
| --- | --- | --- |
| BLP-001 | registered | Processing for `blueprint-by-location-panel` SHALL obtain the selected pilot’s blueprints from a **local provider** |
| BLP-002 | registered | That local provider SHALL implement the **SSE management** of the pilot blueprints |
| BLP-003 | registered | The process to render pilot blueprints on `blueprint-by-location-panel` SHALL **start** with retrieval from that local provider |
| BLP-009 | registered | The local provider SHALL be implemented as **`PilotBlueprintProviderService`** under `modules/services/` (significant name + `.service` suffix) so it is available to **all panels** |
| BLP-010 | registered | The local provider SHALL **cache** elements obtained from the SSE feed |
| BLP-011 | registered | When the cache **expires**, the local provider SHALL be able to **initiate a new retrieval** |
| BLP-012 | registered | Retrieved elements SHALL be uniquely identified by the **`id` attribute**; merge of new data with cached data SHALL be by that `id` (straightforward upsert) |
| BLP-013 | registered | Elements from the local provider SHALL **always** be `neocom-front` domain models that **inherit from** `NeoCom` |
| BLP-024 | registered | Cached blueprint lists SHALL be **keyed by pilot** so **multiple pilots’ lists coexist** in the cache, each with its **own expiration**; expiry / re-fetch for one pilot SHALL NOT clear another pilot’s cache |
| BLP-025 | registered | Per-pilot blueprint cache **expiration SHALL be 60 minutes**, matching ESI [Get character blueprints](https://developers.eveonline.com/api-explorer#/operations/GetCharactersCharacterIdBlueprints) |
| BLP-004 | registered | Blueprints from the local provider SHALL be aggregated into **Systems** and **Regions** per EPIC-010 **IND-BP-033** and **IND-BP-112…115**, **IND-BP-117** |
| BLP-005 | registered | After aggregation, Region roots SHALL be **sorted by name** before hand-off to rendering |
| BLP-006 | registered | Sorted Region roots SHALL be **provided to the node-rendering** path for `blueprint-by-location-panel` (EPIC-002 collaborate / EPIC-010 **IND-BP-116**) |
| BLP-007 | registered | Blueprint hierarchy leaves on `neocom-front` SHALL use a new domain class **`BlueprintNodeV1`** that **inherits from** `NeoCom` |
| BLP-008 | registered | **Region** and **System** hierarchy nodes on `neocom-front` SHALL likewise be **new domain classes that inherit from** `NeoCom` (same pattern as `BlueprintNodeV1`) |
| BLP-016 | registered | On reception, `SpaceLocationV1Dto` SHALL be transformed to `neocom-front` **`SpaceLocationNodeV1`** (inherits from `NeoCom`) |
| BLP-017 | registered | `SpaceLocationNodeV1` SHALL be **tied to the blueprint** so processing can extract **region** and **system** identifiers for aggregation |
| BLP-021 | registered | Real-time updates SHALL use approach A: shared `Observable` on `PilotBlueprintProviderService` with `shareReplay` / `refCount`, emitting `NeoCom[]` / upserts (panels SHALL NOT open blueprint SSE) |
| BLP-022 | registered | On each stream emission, `blueprint-by-location-panel` SHALL **re-aggregate / re-sort** and **`notifyDataChanged`** |
| BLP-023 | registered | Delivery set: provider `observeBlueprints` + shareReplay/refCount, NeoCom nodes, aggregation helper, panel subscription, tests; supersede panel `NodeListAdapterService` SSE for this page |
