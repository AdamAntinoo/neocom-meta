| ID | Status | Requirement |
| --- | --- | --- |
| DASH-001 | registered | After `index.html`, the application goes to the initial landing page. The page is under the authentication protocol. At this stage every page is treated as authenticated, so the Angular filter result is a successful authentication |
| DASH-002 | registered | The initial landing page is the dashboard page under `app/pages` |
| DASH-003 | registered | The dashboard receives a Pilot identifier for data and display. Route parameters are not used. The identifier is a cookie. Proposed cookie name: `neocom-pilot-id`. Until login works, the cookie is initialized to the test value `93813310` |
| DASH-004 | registered | The dashboard page has 2 rows, 2 sections, and 3 components |
| DASH-005 | registered | The top row is the first section, named `header`. The section is borderless. It contains `app-info-panel` and, next to it, `server-info-panel` |
| DASH-006 | registered | The second row is the section named `pilot-dashboard`. It contains the component `pilot-public-info` |
| DASH-007 | registered | The second row may contain an exception component named `exception` when the page receives an exception. How an exception is passed is not defined yet. Every page shows exception data under the `header` section. That is a page pattern |
| DASH-008 | registered | Panels and components use a box decoration class `panel-` followed by a colour. Sections decompose into rows or columns, and that decomposition defines the gap |
| DASH-009 | registered | `app-info-panel` uses colour white. `server-info-panel` uses colour blue. The pilot panel uses colour green |
