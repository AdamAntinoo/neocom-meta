| ID | Status | Requirement |
| --- | --- | --- |
| STRUCT-001 | registered | A page is a routed screen. A panel is a piece of a page and has no route of its own. A section of the application is an Angular module under `app/modules` that owns the pages and panels of that section. The root router loads a section with `loadChildren`. The section module registers its routes with `RouterModule.forChild`. |
| STRUCT-002 | registered | `app/pages` holds the screens of the application shell. The root routes them directly: `login` to `login-page`, `login-callback` to `login-callback-page`, and `dashboard` to `dashboard-home-page`. `dashboard` is behind `authGuard`. The empty path redirects to `dashboard`. |
| STRUCT-003 | registered | `app/panels` holds panels used only by those core pages. They are not routes. The login validation page is built from `login-validation-progress` and `login-validation-exception`. |
| STRUCT-004 | registered | A panel used on core pages and on other pages belongs in `modules/header`. It is declared and exported there, not in `app/panels`. `app-info-panel`, `server-info-panel`, and `v1-pilot-panel` follow that rule. A core page can host them. A section page can host them too. |
| STRUCT-005 | registered | Section modules: only industry (including manufacture) is in scope for this epic. Industry is `modules/industry`, root path `industry`, pages in `modules/industry/pages`. Manufacture is `modules/industry/manufacture`, root path `industry/manufacture`, pages in `modules/industry/manufacture/pages`. Industry and manufacture use the folder names `pages` and `panels`. Each section page composes its own panels and can also compose shared header panels. Planetary, loyalty, fittings, and later sections are deferred until a future requirement needs them. |
| STRUCT-006 | registered | These modules supply pieces to pages. They do not represent an application section and they do not own a root route: `modules/header` holds shared header panels, `modules/shared` holds shared panels, renders, and the viewer, `modules/renders` holds render components for fittings, planetary, loyalty, and industry, `modules/common` holds pipes and small components such as `v1-feature-button`, and `modules/innovative-core` holds base components and services. |
| STRUCT-007 | registered | New core screens go in `app/pages`. New panels used only by core pages go in `app/panels`. New panels used on core pages and on other pages go in `modules/header`. A screen that belongs to a section goes in that section module, with that section's panels beside it. |
