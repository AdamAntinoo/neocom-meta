## Section 01 — Drop unused dogma fields from EveItemV1Dto

**Optimization:** reduce back → front wire size. Programme front does **not** read dogma on items/assets.

Today `EveItemV1Dto` (and therefore nested `PricedItemV1Dto` on assets / priced-item responses) carries optional:

| Field | Wire shape today |
| --- | --- |
| `dogmaAttributes` | `{ attributeId, value }[]` (from ESI `dogma_attributes`) |
| `dogmaEffects` | `{ effectId, isDefault }[]` (from ESI `dogma_effects`) |

Mapped in `neocom-back` `EveItemV1Dto` / `EveItemDtoConverter`. Front has no consumers of these fields.

| ID      | Review          | Requirement                                                                                                                                                                                                                     |
| ------- | --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| OPT-001 | `registered` | Backend SHALL **remove** `dogmaAttributes` and `dogmaEffects` from `EveItemV1Dto` (and stop mapping them in the Eve item converter) so they are not serialized on item / priced-item / nested asset `item` payloads             |
| OPT-002 | `registered` | Related types (`EveItemDogmaAttribute` / `EveItemDogmaEffect` and converter branches) SHALL be removed or left unused only if still required elsewhere; prefer **delete** with the DTO fields when nothing else references them |
| OPT-003 | `registered` | This change is justified because the **front application does not use** dogma attributes or effects; do not reintroduce them unless a later reviewed L1 requirement needs them                                                  |
